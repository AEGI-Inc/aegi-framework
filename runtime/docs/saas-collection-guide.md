# AEGI 6대 SaaS Adapter 실환경 API 수집 세팅 매뉴얼

각 SaaS별로 엔진이 지원하는 **수집 방법(OAuth 및 API Key·자격증명 직접 입력)**, 수집 커버리지를 결정하는 **필요 권한 계정(1순위~후순위)**, 그리고 실제 콘솔에서의 **발급 및 연동 방법**을 정리한 기준표입니다.

* **공통 로컬 콜백 URI**: `http://127.0.0.1:5199/__aegi/oauth/callback`
* **Salesforce 전용 콜백 URI**: `http://localhost:5199/__aegi/oauth/callback` (`127.0.0.1` 대신 `localhost` 필수)
* **Slack OAuth 콜백 URI**: `https://127.0.0.1:5199/__aegi/oauth/callback`

## SaaS 1. GitHub (Organization & Enterprise)

* **필수/선택 식별자**: `GITHUB_ORG` (필수) / `GITHUB_ENTERPRISE` (엔터프라이즈 수집 시 선택)
* **1순위에서 기업이 직접 해야 하는 일**: 대시보드에서 **[새 GitHub App 생성 (Manifest)]** 버튼으로 사내 전용 GitHub App을 자동 생성한 뒤 대상 조직(·엔터프라이즈)에 Install 승인 1회 *(SAML `"Overwrite your linked identity?"` 화면이 나오면 멈추고 관리자에게 확인)*

| 수집 방법 (우선순위 순) | 필요한 계정 (후순위까지) | 발급 방법 |
| :--- | :--- | :--- |
| **1순위 (권장)**<br>**자체 GitHub App 생성 (Manifest · 권한 40종)**<br>• 대시보드 Manifest 버튼으로 사내 전용 GitHub App(권한 40종)을 1-클릭 생성하면 App ID와 개인키(PEM)가 로컬에 자동 저장됨<br>• 조직 및 엔터프라이즈 설치 시 로컬 콜백이 `target_type`(`Organization` vs `Enterprise`)을 자동 감지하여 저장<br>• 환경변수: `GITHUB_APP_ID`, `GITHUB_APP_INSTALLATION_ID`, `GITHUB_APP_ENTERPRISE_INSTALLATION_ID`, `GITHUB_APP_PRIVATE_KEY` | **1순위 (전수 수집)**<br>**Enterprise Owner + Organization Owner**<br>• 조직 리소스(GH-01~17, 21, 24~34) 및 엔터프라이즈 감사 로그(GH-19)까지 앱 설치만으로 즉시 수집 가능<br><br>**2순위 (조직 전수 수집)**<br>**Organization Owner (조직 소유자)**<br>• 엔터프라이즈 전용 호출(GH-19, 20, 22, 23)을 제외한 조직/저장소/브랜치 보호/Actions/웹훅/조직 감사로그 전체 수집 가능<br><br>**후순위 (설치 불가)**<br>**Organization Member (일반 멤버)**<br>• 직접 설치 권한 없음 (Install 클릭 시 Owner에게 승인 요청만 전송됨) | 1. 대시보드 **GitHub 연결 > [자격증명 직접 입력]** 탭 열기<br>2. **[새 GitHub App 생성 (Manifest)]** 버튼 클릭 (40종 권한 자동 포함, 읽기 중심 + API 요구 3종 write 포함)<br>3. GitHub에서 앱 생성 승인 후 콜백 페이지의 **[조직에 앱 설치하기]** 클릭 (`GITHUB_APP_ID`와 개인키 `.pem` 자동 저장)<br>4. SAML SSO가 켜진 조직에서 **`"Overwrite your linked identity?"`** 화면이 나오면 멈추고 조직 관리자에게 기존 SAML 연결 덮어쓰기 여부를 확인한 뒤 진행<br>5. 대상 **Organization**을 선택해 `All repositories`로 **Install** (`GITHUB_APP_INSTALLATION_ID` 자동 저장)<br>6. 엔터프라이즈 감사 로그(GH-19)도 수집하려면 생성된 앱 설정에서 대상 **Enterprise**에도 추가 설치 (`GITHUB_APP_ENTERPRISE_INSTALLATION_ID` 자동 저장) |
| **1순위 보조 (엔터프라이즈 보강)**<br>**Enterprise Owner Classic PAT (소유자 토큰)**<br>• GitHub API 정책상 GitHub App 설치 토큰으로는 호출이 거부(FORBIDDEN)되는 엔터프라이즈 GraphQL 및 SAML 외부 신원 매핑(GH-20, GH-22, GH-23) 수집 시 보조로 함께 등록<br>• 환경변수: `GITHUB_OWNER_TOKEN` | **1순위 (필수)**<br>**Enterprise Owner 겸 Organization Owner**<br>• 엔터프라이즈 SAML SSO Identity 매핑(GH-20) 및 엔터프라이즈 GraphQL(GH-23) 조회 권한 보유<br><br>**후순위**<br>**일반 Organization Owner / Member**<br>• Enterprise 레벨 GraphQL 조회 시 403/FORBIDDEN 반환 | 1. GitHub 우측 상단 프로필 > **Settings > Developer settings > Personal access tokens > Tokens (classic)** 이동<br>2. **Generate new token (classic)** 클릭 후 `read:enterprise`, `read:org`, `read:audit_log`, `repo` 스코프 체크하여 발급<br>3. 조직에 SAML SSO가 켜져 있다면 발급된 토큰 우측 **[Configure SSO] > [Authorize]** 반드시 클릭<br>4. 발급된 `ghp_...` 토큰을 대시보드 `GITHUB_OWNER_TOKEN` 칸에 저장 |
| **2순위**<br>**자체 GitHub OAuth App 로그인 (기본 10개 scope)**<br>• 사내 GitHub OAuth App의 Client ID/Secret을 등록해 브라우저 OAuth 로그인으로 사용자 토큰을 발급받아 수집 (`manage_runners:enterprise` 포함 10개 기본 체크)<br>• 환경변수: `GITHUB_OAUTH_CLIENT_ID`, `GITHUB_OAUTH_CLIENT_SECRET`, `GITHUB_COLLECTOR_OAUTH_TOKEN` | **1순위**<br>**Organization Owner (+ Enterprise Owner)**<br>• 조직 설정, 웹훅(`admin:org_hook`), 러너/시크릿 메타데이터(`admin:org`), 감사 로그(`read:audit_log`)까지 전체 수집<br><br>**후순위 (부분 수집)**<br>**Organization Member (일반 멤버)**<br>• 관리자 전용 호출(웹훅, 감사로그, 시크릿/러너 설정 등)이 403으로 제외되며 본인 접근 가능 저장소만 수집됨 | 1. `github.com/settings/developers` > **OAuth Apps > New OAuth App**에서 Callback URL을 `http://127.0.0.1:5199/__aegi/oauth/callback`으로 등록<br>2. Client ID와 Client Secret을 대시보드 **[OAuth로 연결]** 탭에 입력하고 **[OAuth로 연결 시작]** 클릭<br>3. GitHub 동의 창에서 대상 조직 옆 **Grant / Authorize**를 눌러 승인 |

## SaaS 2. Okta

* **필수 식별자**: `OKTA_ORG_URL` (예: `https://<company>.okta.com`, `-admin` 포함 시 자동 정규화)
* **1순위에서 기업이 직접 해야 하는 일**: Okta Admin Console에서 Read-only Admin(또는 Super Admin) 계정으로 허용 네트워크(`Any IP` 등)를 선택해 SSWS API 토큰 1개 발급

| 수집 방법 (우선순위 순) | 필요한 계정 (후순위까지) | 발급 방법 |
| :--- | :--- | :--- |
| **1순위 (권장 · 가장 빠름)**<br>**Okta API Token (SSWS 토큰 직접 입력)**<br>• 별도의 OAuth 앱 생성이나 59개 스코프 개별 Grant 클릭 없이, 토큰을 발급한 관리자의 읽기 권한을 그대로 상속받아 10초 만에 전수 수집(OK-01~23 및 카탈로그 전체)<br>• 환경변수: `OKTA_ORG_URL`, `OKTA_API_TOKEN` | **1순위 (최소권한 권장)**<br>**Read-only Administrator (읽기 전용 관리자)**<br>• 조직, 사용자, 그룹, 관리자 역할 배정, 앱, OAuth 클라이언트, 정책, System Log, API 토큰 메타데이터, IdP, Authenticator 등 전체 API 100% 조회 가능하며 변경 위험이 없음<br><br>**동순위 (전수 수집)**<br>**Super Administrator (최고 관리자)**<br>• 모든 읽기 API 100% 조회 가능<br><br>**후순위 (부분 수집)**<br>**Org Admin / Group Admin / Report Admin**<br>• 권한 범위 밖의 호출(역할 배정 OK-05/06, IdP 키 OK-18/20, OAuth 통합 OK-15 등)에서 403 Forbidden 발생 | 1. Okta Admin Console(`https://<org>-admin.okta.com`)에 Read-only Admin 또는 Super Admin으로 로그인<br>2. 좌측 메뉴 **Security > API > Tokens** 탭으로 이동<br>3. **[Create token]** 클릭 후 이름(예: `aegi-collector`)을 입력하고, **네트워크 존(`API calls made with this token must originate from`)에서 `Any IP` 또는 회사 네트워크 영역을 선택**해 생성 *(비워 두면 `Provide valid network zones` 오류 발생)*<br>4. 생성된 `00...` 토큰 값을 복사해 대시보드 **Okta 연결 > [자격증명 직접 입력]** 탭에 `OKTA_ORG_URL`과 `OKTA_API_TOKEN` 붙여넣고 저장 |
| **2순위**<br>**OIDC Native App + PKCE OAuth 로그인 (scope 59개)**<br>• 정적 SSWS 토큰 발급을 지양하는 환경에서 OIDC 앱을 등록하고 브라우저 OAuth 로그인으로 갱신 토큰(`refresh_token`)을 발급받아 수집<br>• 환경변수: `OKTA_ORG_URL`, `OKTA_COLLECTOR_CLIENT_ID`, `OKTA_COLLECTOR_REFRESH_TOKEN` | **앱 생성 및 Scope Grant**<br>**Super Administrator (최고 관리자)**<br>• OIDC 앱 생성 및 `Okta API Scopes` 탭에서 59개 스코프 Grant 승인에 필요<br><br>**OAuth 로그인 계정**<br>**Read-only Administrator 이상**<br>• 해당 앱에 Assign 되어 있고 Read-only Admin 이상 역할을 가진 계정으로 로그인 시 전수 수집 | 1. Okta Admin Console > **Applications > Applications > Create App Integration** 클릭<br>2. **OIDC - OpenID Connect** + **Native Application** 선택 후 생성<br>3. Grant type에 `Authorization Code`, `Refresh Token` 체크, Redirect URI에 `http://127.0.0.1:5199/__aegi/oauth/callback` 입력 후 Save<br>4. **Okta API Scopes** 탭에서 필요한 59개 스코프(`okta.*.read` 58개 + `ssf.read`)를 Grant하고, **Assignments** 탭에서 관리자 계정 배정<br>5. General 탭의 **Client ID**를 대시보드 **[OAuth로 연결]** 탭에 입력하고 **[OAuth로 연결 시작]** 클릭 |
| **3순위 (무인 서버 간 통신)**<br>**API Services App (`private_key_jwt` + DPoP · scope 59개)**<br>• 사용자 로그인 없이 비대칭키(RSA PEM) 서명과 DPoP 증명으로만 토큰을 발급받는 서비스 앱 방식<br>• 환경변수: `OKTA_ORG_URL`, `OKTA_COLLECTOR_CLIENT_ID`, `OKTA_COLLECTOR_KEY_ID`, `OKTA_COLLECTOR_PRIVATE_KEY` | **1순위 (필수)**<br>**Super Administrator (앱 설정 및 역할 부여)**<br>• API Services 앱 자체의 **Admin Roles** 탭에 `Read-only Administrator` 역할을 직접 배정해야 호출이 허용됨 | 1. **Applications > Create App Integration > API Services** 선택 후 저장<br>2. General 탭 **Client Credentials > Edit**에서 `Public key / Private key` 선택 > **Add key > Generate new key** 클릭<br>3. 생성된 JWK의 `kid`(Key ID)와 PEM 개인키 복사 후 Save<br>4. **Okta API Scopes** 탭에서 59개 스코프를 Grant하고, **Admin Roles** 탭에서 `Read-only Administrator` 배정 |

## SaaS 3. Slack (Workspace & Enterprise Grid)

* **필수/선택 식별자**: `SLACK_TEAM_ID` (OAuth 동의 시 자동 감지) / `SLACK_ENTERPRISE_ID` (Enterprise Grid인 경우)
* **1순위에서 기업이 직접 해야 하는 일**: Slack API 콘솔에서 App Manifest로 사내 전용 Slack 앱 생성 후 OAuth 로그인(Client ID/Secret 입력) 또는 Bot·User 토큰 직접 입력 + **(Enterprise Grid) 조직 관리에서 `Add to more workspaces`로 워크스페이스 추가**

| 수집 방법 (우선순위 순) | 필요한 계정 (후순위까지) | 발급 방법 |
| :--- | :--- | :--- |
| **1순위 (권장)**<br>**자체 Slack App OAuth 로그인 (기본 scope 23개)**<br>• 사내 전용 Slack App의 Client ID·Client Secret을 대시보드에 입력하고 OAuth 동의 1회로 Bot 토큰(`xoxb-`)과 관리자 User 토큰(`xoxp-`), `SLACK_TEAM_ID`를 자동 발급·저장<br>• 환경변수: `SLACK_CLIENT_ID`, `SLACK_CLIENT_SECRET`, `SLACK_COLLECTOR_BOT_TOKEN`, `SLACK_COLLECTOR_USER_TOKEN`, `SLACK_TEAM_ID` | **1순위 (Enterprise Grid 환경)**<br>**Enterprise Grid Org Owner / Org Admin**<br>• 워크스페이스 기본 수집(SL-00~07) + 조직 전체 채널/사용자/IdP 그룹(`admin.*`) + 조직 감사 로그(`auditlogs:read`, SL-11)까지 100% 수집<br><br>**1순위 (일반 플랜 환경)**<br>**Workspace Primary Owner / Owner / Admin**<br>• Pro / Business+ / 무료 워크스페이스에서 지원하는 모든 사용자, 채널, 봇, 사용자 그룹 및 통합 로그(`team.integrationLogs`, SL-09) 수집 가능<br><br>**후순위 (일반 멤버)**<br>**Workspace Member (일반 사용자)**<br>• 앱 설치 승인 권한이 없으면 설치 불가. 설치되더라도 관리자 API 및 감사/통합 로그 호출 불가 | 1. `https://api.slack.com/apps` > **Create New App > From a manifest**로 사내 수집용 앱 생성 (Redirect URL: `https://127.0.0.1:5199/__aegi/oauth/callback`)<br>2. 대시보드 **Slack 연결 > [OAuth로 연결]** 탭에서 앱의 `Client ID`와 `Client Secret` 입력 후 **[OAuth로 연결 시작]** 클릭<br>3. Slack 동의 화면에서 대상 워크스페이스/조직 선택 후 **Allow** 클릭 *(로컬 HTTPS 콜백 경고가 뜨면 `[고급] > [127.0.0.1로 이동]` 1회 클릭)*<br>4. **(Enterprise Grid 필수)** Slack 조직 관리(`Manage organization > Integrations > Installed apps`)에서 **`Add to more workspaces`**로 수집 대상 워크스페이스를 추가하고 **`Who can use?`** 단계에서 **`Save`** 완료 *(미완료 시 `team_access_not_granted`)*<br>*(참고: 비공개 채널 SL-03/04 및 채널 메시지 SL-05는 수집 봇이 채널에 초대되어 있어야 조회 가능)* |
| **2순위 (직접 입력)**<br>**App Manifest 자체 앱 설치 후 토큰 직접 입력**<br>• OAuth 콜백 없이 Slack API 콘솔에서 앱을 바로 설치해 발급된 Bot/User 토큰을 붙여넣어 연동<br>• 환경변수: `SLACK_COLLECTOR_BOT_TOKEN`, `SLACK_COLLECTOR_USER_TOKEN` | **1순위**<br>**Workspace Owner / Admin 또는 Org Admin**<br>• 사내 워크스페이스/조직에 앱 생성 및 설치 승인 권한 보유 | 1. `https://api.slack.com/apps` 접속 > **Create New App > From a manifest** 클릭<br>2. 대상 워크스페이스를 선택하고 AEGI 수집용 매니페스트(Bot 7~8개 + User 16개 read 스코프 포함)를 붙여넣어 앱 생성<br>3. 좌측 **OAuth & Permissions > Install to Workspace(또는 Organization)** 눌러 승인<br>4. 화면에 표시된 `Bot User OAuth Token (xoxb-...)`과 `User OAuth Token (xoxp-...)`을 대시보드 **[자격증명 직접 입력]** 탭에 붙여넣기 |
| **보조 (선택 · SL-10 / `app_configurations:read` 전용)**<br>**App Configuration Token (앱 매니페스트·함수 배포 권한 조회용)**<br>• 워크스페이스 내 설치된 앱들의 매니페스트 상세(SL-10, `apps.manifest.export`) 및 워크플로 함수 배포 권한(`functions.distributions.permissions.list`) 수집용 Configuration 토큰 (12시간 만료, Refresh Token 자동 회전 지원)<br>• 환경변수: `SLACK_CONFIG_TOKEN`, `SLACK_CONFIG_REFRESH_TOKEN` | **1순위**<br>**대상 Slack App의 Collaborator / Owner 계정**<br>• 워크스페이스에 등록된 앱들의 설정에 접근 권한이 있는 관리자 계정 | 1. `https://api.slack.com/apps` 페이지 맨 아래 **Your App Configuration Tokens** 섹션 이동<br>2. **[Generate Token]** 클릭 후 대상 워크스페이스를 선택해 생성<br>3. 발급된 Access Token(`xoxe.xoxp-...`)을 대시보드 `SLACK_CONFIG_TOKEN` 칸에 입력 |

## SaaS 4. Google Workspace
