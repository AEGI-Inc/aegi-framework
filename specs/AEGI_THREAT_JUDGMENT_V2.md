# 위협 판정 명세 V2

작성: 2026-11-11. 상태: 확정. 7절 기본값 6개 사람 확인 끝(2026-11-11).

위협은 비인가 접근, 권한 상승, 데이터 반출, 추적성 상실 네 유형(2026-11-19 결정). 유형의 이름, 뜻, 가르는 기준의 정본은 aegi-knowledge `schema/ontology/threat_types.yaml` 이고 엔진은 `ontology:sync` 로 받아 `src/ontology/generated.ts` `THREAT_TYPES` 로 씀. 그래프 경로로 성립하는 것만 판정. 앞의 세 유형은 사람, 대상마다 가진 접근이 기준선보다 높은 수준(Access Gap)에서 가름. 기준선은 조직 안이 직접 권한, 조직 밖이 없음(승인 목록에 있으면 읽기). 추적성 상실은 고정 실행 신원마다 따로 봄(2026-11-18 결정, aegi-adapter-engine#489).

이 명세가 대체하는 문서: `AEGI_FINDING_CLASSIFICATION_V1.md`, `AEGI_GENERIC_ACCESS_ENGINE_V1.md` 판정 부분, `AEGI_GROUND_TRUTH_GENERIC_DETECTION_V1.md`. 옛 문서는 단계 9에서 이력 표시.

## 1. 범위

| 구분 | 내용 |
|---|---|
| 판정하는 것 | 비인가 접근, 권한 상승, 데이터 반출, 추적성 상실. 그래프 경로로 성립하는 것만 |
| 전제 | SaaS 안 내용은 전부 개인정보. 민감도는 따지지 않음. 추적성 상실은 대상 감사 로그가 있다는 전제에서만 판정 |
| 위협 아님 | 의도한 공개(공개 저장소, 웹 게시 문서, 공개 폼). 이미 가진 권한의 다른 통로. 제어 객체 읽기만 새로 생긴 경우. 본인 객체에 대한 효과 |
| 못 하는 것 | 내부자 대량 다운로드처럼 그래프 경로가 없는 행위. 감사 로그 끄기, 보존 기간 줄이기 같은 단일 설정. 레코드, 필드 단위 노출 |
| 범위 밖 | 데이터 구멍: 조직 경계 입력, 승인 목록 수집, SaaS 사이 자원 안 자격증명 실데이터, Okta 외 감사 로그 정규화. 판정 코드는 입력 자리만 둠. 입력이 없으면 「모름」으로 미확정 |
| 유형 밖 | 피해 범위(토큰 유출 가정)는 자격증명 상세에 남김. 단일 설정 문제는 설정 점검 목록 |

「못 하는 것」은 문서와 화면에 「한다」고 쓰지 않음.

## 2. 용어

| 용어 | 정의 | 영어 |
|---|---|---|
| 직접 간선 | 소속, 범위, 권한 | Direct edge |
| 파생 간선 | 호출, 실행 신원, 데이터 흐름, 효과 | Derived edge |
| 직접 권한 | 직접 간선만으로 닿는 곳과 수준. 그 SaaS 설정이 원래 허락한 것. 옛 이름 직접 권한(2026-11-16 바꿈) | Direct permission |
| 파생 접근 | 파생 간선을 하나 이상 거쳐 닿는 접근 | Derived access |
| 내용 객체 | interface가 Resource인 객체. 파일, 메시지, 레코드, 채널, 저장소 | Content object |
| 제어 객체 | interface가 Policy, Assignment, Integration, Automation, Credential, Endpoint, Principal인 객체 | Control object |
| 승인 목록 | 고객이 AEGI에 등록한 목적지, SaaS 관리자 허용 목록, 공개 의도 등록 | Approved destinations |
| 고정 실행 신원 | 호출자와 상관없이 같은 신원으로 실행. 토큰, 서비스 계정, 여럿이 쓰는 사람 계정 | Fixed run identity |
| 기준선 | Access Gap 에서 원래 가져도 되는 접근. 조직 안은 직접 권한. 조직 밖은 없음(사내에 공유할 수 있는 권한이 밖에 공유해도 된다는 뜻은 아님), 승인 목록에 있으면 승인 범위인 읽기(2026-11-18 결정) | Baseline |
| Access Gap | 사람, 대상마다 가진 접근 가운데 기준선보다 높은 수준. 가진 접근은 조직 안이 파생 접근, 조직 밖이 직접 공유와 파생 접근 | Access Gap |
| 연동 지점 | 접근을 넘겨준 파생 간선의 객체. 실행 신원은 자동화, 자원 안 자격증명은 그 자원, 데이터 흐름은 옮기는 자동화나 사본 위치, 효과는 출발 객체. 같은 수준을 주는 것이 여럿이면 5절 「파생 접근」의 고르는 순서로 하나. 직접 공유는 대상 자신 | Integration point |

## 3. 간선

간선 7종. 지금 `EdgeIndex` 종류 그대로이고 판정 쪽에서 새 간선 종류를 만들지 않음(2026-11-15 결정). object 스키마와 relation 규칙은 고치지 않음.

자원 안에 든 자격증명(Credential)은 relation 효과 표가 낸 범위 간선으로 자원 아래에 놓임. 그 자원을 읽을 수 있는 사람은 자격증명을 꺼내 자격증명의 실행 신원(없으면 자격증명 자신)으로 동작함. 판정 이유 이름은 「자격 보관」. 테넌트 바로 아래 자격증명은 테넌트 권한으로 꺼내지 않음. relation 효과 표가 범위를 내지 않는 쌍(`owned_by` 로 자원에 묶인 자격증명)은 판정하지 않음. 실물(개인 키)이 SaaS 밖에 있는 자격증명(Profile 상수 `credential_kind` 가 `ssh_key`, `key_pair`, `certificate`)은 SaaS 에 공개 부분만 있어 자원을 읽어도 꺼내지 못함(2026-11-16). GitHub 배포 키는 「the private part of the key remains on your server」(https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys).

정책 조건(`evaluates`, `applies_to`)과 Okta 그룹 규칙의 본인 편집 속성은 판정하지 않음. relation 효과 표가 간선을 내지 않기 때문.

| 이름 | 구분 | 지금 코드 | 출처 |
|---|---|---|---|
| 소속 | 직접 | `M` | 기존 |
| 범위 | 직접 | `U` | 기존 |
| 권한 | 직접 | `G` | 기존 |
| 호출 | 파생 | `T` | 기존 |
| 실행 신원 | 파생 | `A` | 기존 |
| 데이터 흐름 | 파생 | `F` | 기존 |
| 효과 | 파생 | `E` | 기존 |

간선 속성

| 속성 | 값 | 출처 |
|---|---|---|
| 수준 | 읽기, 쓰기, 관리 세 개의 켜짐 값. 비트 3개 | `ontology/capabilities.yaml` rank(읽기 1, 쓰기 3, 관리 5)에서 변환. 1 이상 읽기, 3 이상 쓰기, 5 이상 관리 |
| 게시 전용 | 참, 거짓 | 웹훅 게시, 폼 제출. 쓰기만 켜고 읽기는 켜지 않음 |
| 허용 호출자 | 목록 또는 모름 | 호출 간선. 모르면 미확정 |
| 동작 범위 | 목록 또는 모름 | 실행 신원 간선. 모르면 미확정, 사유 「능력 범위 모름」(2026-11-16 결정) |
| 확실성 | 확정, 미확정과 사유 | 기존 `uncertain` |
| 출처 | 근거 관계 키 | 기존 `refs` |

고정 실행 신원은 Automation의 `run_as_resolution`, 정지 계정은 Principal의 `account_state`를 그대로 읽음.

## 4. 판정 흐름

| 순서 | 단계 | 하는 일 |
|---|---|---|
| 1 | 검사 대상 | 조직 안은 파생 간선이 닿는 대상만. 조직 밖은 파생 간선이나 직접 공유가 닿는 대상 |
| 2 | 직접 권한 | 사람마다 같은 사람 계정 전부가 직접 간선만으로 닿는 객체와 수준. 5절 「직접 권한」 |
| 3 | 파생 접근 | 사람마다 직접 권한에서 출발해 파생 단계를 따라 수준이 더 안 오를 때까지 폄. 파생 단계를 하나 이상 지난 것만 남김. 데이터 흐름은 사본 쪽을 읽는 사람이 원본을 읽음. 5절 「파생 접근」 |
| 4 | Access Gap | 사람, 대상마다 기준선과 가진 접근을 비교해 기준선보다 높은 수준을 셈. SaaS별 계정이 같은 사람이면 하나로. 같은 사람인지 모르면 미확정. 8절 「Access Gap」 |
| 5 | 유형 | Access Gap 줄만 읽고 5절 규칙 표로 비인가 접근, 권한 상승, 데이터 반출을 가름 |
| 6 | 마무리 | 건수, id, 대표 유형, 심각도, 차단 지점 |

추적성 상실은 4번 Access Gap 을 쓰지 않고 고정 실행 신원마다 따로 훑음.

## 5. 확정 규칙

적대적 검증 3건(보안 담당자 검토, 사례 45개 시뮬레이션, 실측 데이터 대조) 반영. 옛 규칙 18/45 일치, 이 규칙 41/45.

| # | 규칙 | 내용 |
|---|---|---|
| 1 | 행위 수준 | 읽기, 쓰기, 관리 세 개의 켜짐 값. 파생 읽기는 데이터 흐름과 자원 안 자격증명으로만 생김. 실행 신원과 효과는 쓰기만 줌. 게시 전용 쓰기는 읽기 없음, 심각도 낮음 |
| 2 | 새로 생긴 것 | 사람, 대상마다 기준선과 가진 접근 비교(Access Gap). 새 읽기, 새 쓰기, 새 관리를 각각 판단. 기준선에 없고 가진 접근에 있는 비트가 새로 생긴 것. 조직 안은 직접 값과 파생 값 |
| 3 | 객체 분류 | object 스키마 interface 그대로. 2절 내용 객체, 제어 객체. 새 분류 표 없음. 채널, 저장소 같은 담는 객체는 Resource라 내용 객체 |
| 4 | 유형 | Access Gap 줄만 읽음(2026-11-18 결정). 기준선에 읽기, 쓰기, 관리가 모두 없던 사람이 새 접근을 얻으면 비인가 접근, 기준선에 접근이 있던 사람이 더 높은 수준을 얻으면 권한 상승. 게시 전용만 있던 사람이 읽기를 얻어도 권한 상승. 조직 안과 밖이 같음(2026-11-19 결정). 내용 객체와 다른 사람 프로필은 새 읽기부터, 새 쓰기와 새 관리는 대상과 상관없이 셈. 제어 객체와 그룹에 읽기만 새로 생긴 것은 위협 아님(옛 「그룹, 앱 획득은 수준과 무관하게 권한 상승」은 2026-11-18 지움). 제어 객체 관리를 새로 얻고 그 아래에 기준선으로 못 읽던 내용(공개 의도 등록 뺌)이 있으면 비인가 접근도 붙이고 사유 「아래 내용 읽기」(관리를 얻으면 자기를 구성원으로 넣어 읽음). 새 읽기가 조직 밖 목적지로 가는 데이터 흐름으로 왔으면 그 읽기는 데이터 반출이고 받는 사람에게 비인가 접근, 권한 상승을 붙이지 않음(아래 「데이터 반출」) |
| 5 | 조직 밖 | 기준선은 없음, 승인 목록에 있으면 승인 범위(읽기, 사례 N20). 직접 공유도 기준선 밖이라 새로 생긴 것(2026-11-18 결정). 유형은 규칙 4 그대로: 승인 목록에 없는 사람의 새 접근은 비인가 접근, 승인된 사람이 쓰기 이상을 얻으면 권한 상승. 조직 밖 사람은 유형 이름에 꼬리표를 달지 않고 판정 줄마다 조직 밖 표시(`external`, 2026-11-19 결정). 공개 의도 등록 내용 읽기는 위협 아님. 누구나의 게시 전용 직접 권한(공개 폼 응답)은 위협 아님. 조직 밖 계정은 직원 계정과 약하게 이어져도 합치지 않고(그 직원 프로필을 새로 읽으면 비인가 접근), 직접 수준 모름도 판단을 바꾸지 않음(2026-11-18 결정). 「누구나」는 확정한 조직 밖 |
| 6 | 조직 경계 | 조직이 가진 테넌트와 검증 도메인 기준. 게스트는 밖. 입력 없으면 모름. 메일 도메인만으로 판단하지 않음 |
| 7 | 승인 대조 | 도메인과 주소. 앱 승인은 앱과 목적지 쌍까지 맞아야 승인 |
| 8 | 추적성 상실 | 6절 |
| 9 | 자동화 | 자동화 편집자는 실행 신원 전체 권한. 호출 간선에 허용 호출자 속성, 모르면 미확정. 부르기만 하는 사람은 실행 신원 권한의 쓰기 차원 가운데 동작 범위 안만. 동작 범위를 모르면 미확정(2026-11-16 결정). 동작 목록과 프로젝트 범위가 수집된 규칙(Jira 자동화)은 2026-11-15 결정으로 자름: 편집자는 규칙에 관리 수준이 있는 사람(Administer Jira, 범위 프로젝트 관리자)만, 규칙 제품(Jira) 대상은 범위 프로젝트와 그 아래만. 같은 SaaS 의 다른 제품(Confluence) 내용 대상(space, 페이지)은 범위로 자르지 않음(2026-11-17 결정. 범위는 규칙이 도는 프로젝트를 정하고, 프로젝트 범위 규칙도 Confluence 동작의 space 를 고름, Atlassian AUTO-2415). 다른 제품의 권한 설정, 역할, 자동화 규칙은 규칙 동작이 못 고쳐 뺌. 호출자는 그중 동작이 고치는 제품 자원만(밖으로 보내기, 메일, 로그 기록은 못 고침. Jira 규칙의 Confluence 페이지 수정은 Confluence 만). 다른 SaaS 대상은 자르지 않음. 추적성 상실은 자르지 않음 |

| 11 | 대표 유형 | 여러 유형이 붙으면 데이터 반출, 권한 상승, 비인가 접근, 추적성 상실 순(2026-11-19 결정, 순서 정본 threat_types.yaml `order`, 8절 「심각도」) |
| 12 | 발생과 확실성 | 발생 가능(설정), 발생(로그로 쓰인 것 확인. 데이터 반출은 조직 밖으로 가는 데이터 흐름에 전송 기록이 있어도 발생, 2026-11-19 결정). 확정, 미확정. 데이터 반출의 확실성도 다른 유형처럼 경로 확인으로 정함. 구조상 경로가 확실하면 「발생 가능, 확정」으로 기본 목록에 보임. 약한 계정 연결과 연결 없음(같은 사람인지 모름)은 미확정 |
| 13 | 시작점 | 사람만. 서비스 계정은 실행 신원. 정지 계정, 만료 공유와 토큰은 없음으로 봄 |
| 14 | 삭제 | 「관계 둘 이상」 규칙. 파생 경로는 늘 둘 이상이라 걸러내는 것 없음. 객체 하나의 설정값으로 결론 나면 설정 점검. 조직 밖 수신자는 관계 하나(직접 공유)여도 승인 목록에 없으면 비인가 접근 |

### 유형 표

새 읽기, 새 쓰기는 Access Gap(기준선과 가진 접근의 비교). 조직 밖 사람은 기준선이 없음이라 직접 공유로 받은 접근도 새로 생긴 것(2026-11-18 결정). 기준선 「없음」은 읽기, 쓰기, 관리가 모두 없음(로그인만, 권한 주기만 되는 것도 없음), 「있음」은 하나라도 있음(게시 전용, 조직 밖 승인 범위 포함). 2026-11-19 결정.

| 대상 | 기준선 | 새 읽기 | 새 쓰기 이상 |
|---|---|---|---|
| 내용 객체, 다른 사람 프로필 | 없음 | 비인가 접근 | 비인가 접근 |
| 내용 객체, 다른 사람 프로필 | 있음 | 권한 상승 | 권한 상승 |
| 제어 객체, 그룹 | 없음 | 위협 아님 | 비인가 접근 |
| 제어 객체, 그룹 | 있음 | 위협 아님 | 권한 상승 |

| 덧붙는 경우 | 결과 |
|---|---|
| 새 읽기가 조직 밖 목적지로 가는 데이터 흐름으로 옴 | 그 읽기는 데이터 반출(위 표 유형 대신) |
| 제어 객체 관리를 새로 얻고 그 아래 기준선으로 못 읽던 내용이 있음 | 쓰기 이상 줄에 비인가 접근도, 사유 「아래 내용 읽기」 |
| 조직 밖 사람이 공개 의도 등록 내용을 읽음 | 위협 아님 |
| 승인 목록의 조직 밖 사람이 승인 범위(읽기) 안을 읽음 | 위협 아님. 승인됨으로 Access Gap 벤에만 남김 |
| 받는 쪽 조직 경계 모름 | 조직 밖으로 보고 위 유형을 미확정, 사유 「조직 경계 모름」 |

읽기와 쓰기가 같은 연동 지점, 같은 확실성에서 함께 생기면 한 건으로 셈(유형이 다르면 둘 다 붙음). 연동 지점이 다르면 따로. 읽기 줄과 쓰기 줄은 유형 이름이 같아도(둘 다 비인가 접근) 차원(읽기, 쓰기 이상)으로 가름(2026-11-19).

| 경우 | 결과 |

### 실데이터 채점으로 보강한 규칙 (2026-11-12)

r1, g2, r2 정답 대조(`npm run gt:threat`)에서 찾은 결함을 간선 종류만으로 고친 규칙. SaaS 이름, 시나리오 키 없음.

| 규칙 | 내용 |
|---|---|
| 자동화로 들어간 데이터 | 자동화가 내보내는 곳을 하류 데이터 흐름으로 볼 수 있는 사람이 읽기를 얻음. 나가는 흐름이 없는 자동화는 호출자가 결과를 받는 것으로 봄. 나가는 흐름이 있는데 호출자가 그 끝을 못 보면 호출자 읽기는 미확정(「결과 반환 모름」). 자동화 설정을 읽을 수 있는 것만으로는 데이터를 못 봄 |
| 자동화의 효과 | 자동화에서 나가는 효과 간선은 호출자가 일으킴. 호출자를 확인 못 했으면 미확정 |
| 자동화가 가진 권한 | 자동화가 직접 가진 권한(엔드포인트, 웹훅이 받는 게시 권한)은 자동화 자신을 고정 실행 신원으로 봄 |
| 다른 사람 계정 | 다른 사람 계정은 제어 객체. 쓰기 이상을 새로 얻으면 기준선대로 비인가 접근이나 권한 상승. 읽기를 새로 얻으면 사용자 프로필(내용 객체)을 보는 것이라 같은 규칙(2026-11-13), 조직 밖 사람도 같음(2026-11-19). 테넌트에 받은 권한이 소속 계정에 닿는지는 아래 「직접 권한」 테넌트 범위가 정함(2026-11-16). 같은 사람 계정은 뺌. 약하게 이어진 사람 계정은 조직 안 사람만 뺌(조직 밖 계정은 직원 계정과 이어져도 그 직원 프로필을 새로 읽으면 비인가 접근, 2026-11-18 결정) |
| 내용을 담은 제어 객체 | 범위 아래에 기준선으로 못 읽던 내용 객체가 있는 제어 객체의 관리를 새로 얻으면 비인가 접근도 붙고 사유 「아래 내용 읽기」(스스로 구성원 추가, 사유는 2026-11-19). 승인 목록의 조직 밖 사람은 기준선이 승인 범위(읽기)라 붙지 않음. 미확정 경로에서만 서면 확정 쓰기 판정과 이름이 같아도 미확정 판정을 따로 냄. 심각도 기밀성을 셈 |
| 같은 사람 | 단단한 Link 로 이어진 계정 묶음(대칭, 이행)을 한 사람으로 판정. 직접 권한은 묶음 전체, 위협과 호출자 수는 사람마다 한 번. 진입 간선은 그 간선을 실제로 가진 계정에서 그림. 약한 Link 는 합쳐서 사라지면 미확정(조직 안 사람만. 조직 밖 계정은 직원 계정과 약하게 이어져도 합치지 않음, 2026-11-18 결정). 사라지는지는 대상이 아니라 차원(읽기, 쓰기 이상)마다 봄(같은 대상에 쓰기 이상이 남아도 상대가 이미 읽던 대상의 읽기는 미확정, 2026-11-14). 합친 기준선에서 유형만 바뀌고(비인가 접근이 권한 상승으로) 새 접근이 남으면 확정 그대로이고 유형은 그 사람 기준선대로(2026-11-19 결정). 읽기와 쓰기를 합친 줄에서 한 차원만 사라지면 남는 차원의 줄과 사라진 차원의 미확정 줄로 나눔. 「아래 내용 읽기」도 차원처럼 봄: 합친 기준선으로 아래 내용을 이미 읽으면 쓰기 이상 줄은 그 사유(와 그 사유로 붙은 비인가 접근) 없이 확정, 아래 내용 읽기는 미확정 비인가 접근 줄(2026-11-19 결정). Link 로 사람 계정과 이어진 계정은 사람 계정. 단 서비스 계정, 측정 계정, 연결 근거 없는 계정은 뺌(13). 조직 경계는 입력을 따름 |
| 같은 사람 연결 없음 | 사람 표가 완결이 아니면(사람이 쓴 표가 아닌 실측, `isCompletePersonTable`) 같은 사람 연결이 하나도 없는 조직 안 계정은 「다른 사람」이 아니라 「모름」. 같은 사람일 수 있는 후보는 그 SaaS 계정이 없는 조직 안 사람(한 사람은 한 SaaS 에 계정 하나라 이미 그 SaaS 계정이 있는 사람은 후보가 아님). 같은 SaaS 의 다른 계정이 허브에 연결돼 있으면(맞추기는 되는데 이 계정만 안 맞음) 허브에 연결된 사람은 후보에서 빼고 연결 없는 계정만 후보(11-04 수집본: Okta 에 안 붙은 Salesforce 계정 3개의 회사 도메인 주소는 Okta, GWS 어디에도 없음). 후보의 직접 권한을 합쳐도 남는 차원만 확정, 사라지는 차원(후보가 이미 닿는 대상, 후보의 계정과 거기 딸린 객체)은 미확정 「같은 사람 연결 없음」. 기준은 위 「같은 사람」과 같음. 허브가 없으면 넓게 걸리고, 모든 사람이 연결됐으면 후보가 없어 안 걸림. 위협 수는 그대로이고 확실성만 바뀜(2026-11-14) |
| 직접 수준 모름 | 「모름」 직접 권한(수준 없는 역할, 불확실 간선, 상한 모름)은 직접 권한에 넣지 않고, 그 권한이 닿는 대상의 판정은 미확정. 닿는 곳은 아래 「직접 권한」 규칙 그대로(2026-11-16). 조직 밖 사람은 기준선이 직접 권한과 상관없어 판정을 바꾸지 않음(2026-11-18) |
| 조직 경계 | 벤더가 계정 속성으로 밝힌 게스트, 고객, 외부 워크스페이스 계정만 조직 밖(`boundary.ts`, 근거 문서 주석). 같은 Enterprise Grid 조직의 다른 워크스페이스 계정은 조직 안. 메일 도메인만으로는 안 정함 |
| 벤더 표 중복 | 정규화가 메일함 객체에서 조직 밖 노드까지 닿는 데이터 흐름을 이미 만들었으면 벤더 표는 덧붙이지 않음 |
| 작성자 관리 권한 (2026-11-15) | Apps Script 프로젝트 작성자의 관리 권한은 정규화가 `owned_by`(프로젝트에서 작성자, `decomposable: false`) 관계로 냄. 실행 방식과 상관없이 모든 프로젝트. 벤더 표는 같은 작성자, 프로젝트 사이 관리 권한이 없을 때(관계가 없는 옛 데이터셋)만 덧붙임 |
| 읽기와 쓰기 경로 | 한 사람이 같은 대상에 읽기와 쓰기 이상을 서로 다른 연동 지점이나 확실성으로 얻으면 위협도 따로. 같은 수준을 주는 경로가 여럿이면 확인된 경로, 그다음 키가 작은 연동 지점 |
| 본인 객체 | 같은 사람 계정에 딸린 객체(노드 `owner`, 본인 프로필과 속성)는 대상으로 세지 않음(1절 「본인 객체에 대한 효과」). 거기서 나가는 효과는 따라감. 조직 밖 사람도 읽기, 쓰기 모두 뺌(2026-11-18). 실데이터는 아직 소유 관계를 판정 어휘에 넣지 않아 사례 그래프에만 씀 |
| 한 경로에 한 건 | 범위 위 객체로 묶는 것은 같은 연동 지점, 같은 유형과 차원의 판정끼리. 다른 연동 지점의 경로는 아래 객체라도 따로 남김. 직접 공유는 가장 위의 공유 지점 하나 |
| 사람 아닌 계정 | 수집 호출 번호가 붙은 종류 이름(예: `200.bot`)도 번호를 떼고 서비스 종류 표와 대조 |
| 승인 입력 | 게시 때 대시보드 D1 `destination_approvals`(취소 안 한 행)를 읽어 조직 밖 수신자에 승인, 내용 객체에 공개 의도를 붙임(`approvals.ts`). 주소로 등록한 공개 의도는 그 주소 계정의 메일함. 승인 행 지문이 스냅샷 id 에 들어가 승인을 바꾸면 새 스냅샷. `d1:verify` 도 같은 입력으로 다시 계산 |
| 접속자 권한의 범위 (2026-11-13) | 접속자 권한으로 도는 자동화는 받은 OAuth scope 안에서만 호출자 권한을 빌림(`vendorEdges.ts` `callerScopeCap`). scope 묶음마다 대상 종류를 정하고 `.readonly` 는 읽기. 표에 없는 scope 는 버림. 남는 scope 가 없으면 빌림 간선을 만들지 않음. 다른 SaaS 객체는 빌리지 않음. 테넌트에 받은 권한은 그 테넌트 소속 계정과 그룹에도 펼쳐 scope 와 대조. 같은 연동 지점에서 한 테넌트의 다른 사람 계정 여럿이 대상이면 테넌트 한 건으로 묶음 |

6절 「호출자 전원이 직접 읽기를 가진 대상과 공개 대상은 읽기 단계에서 제외」도 이때 코드에 넣음. 같은 날 적대적 검증 결과(같은 사람 중복, 승인 미반영, 수준 모름 성능과 범위, 결과 반환, 차단 지점 확인)를 반영하고 `scripts/threat/reviewFixes.test.ts` 로 고정.

### 직접 권한 (2026-11-16)

규칙은 엔진 `src/detection/v2/engine/directAccess.ts` 한 곳. 판정(사람 기준으로 펴기)과 Access Gap 엔진(`query.ts` `can`, 대상 기준으로 찾기)이 같은 규칙 함수를 부름. 테넌트 범위 표는 aegi-knowledge `providers.yaml` `tenant_scope`, 수준 표는 `capabilities.yaml` `capability_levels`, `role_flag_reach`(aegi-knowledge#308, aegi-adapter-engine#435).

| 규칙 | 내용 |
|---|---|
| 정의 | 사람마다, 같은 사람 계정 전부가 소속, 권한, 범위 내려가기 간선만으로 닿는 객체와 수준. 실행 신원도 같은 계산 |
| 수준 | 읽기, 쓰기, 관리가 따로. 쓰기만 있으면 게시 전용. 로그인(authenticate)과 권한 주기(grant)는 수준 아님 |
| 테넌트 범위 | 테넌트에 걸린 권한은 출처 종류(소속, 제품 사용, 관리 콘솔 역할, 기본 권한)와 객체 종류(내용, 설정, 계정)로 내려가는 수준이 정해짐. 테넌트 객체 자체는 그 권한 수준. 하위 테넌트, 다른 SaaS 로는 안 내려감. 종류를 모르는 테넌트 권한은 안 내려감 |
| 상태 | 확정, 모름(수준 모름, 불확실 간선, 상한 확인 못 함), 추정(약한 연결 계정으로만 닿음). 판정의 직접 권한은 확정만 |
| 누구나 공유 | 모든 사람의 직접 읽기(공개 문서). 그 대상의 파생 읽기는 새 접근이 아님. 누구나 공유에서 시작하는 파생 접근과 조직 밖 수신자 판정은 누구나 노드가 한 번 냄 |
| 로그에서 확인한 권한 | 직접 권한에 넣고 근거 출처를 따로 적음 |
| 실행 신원의 모름 | 신원이 빌려 주는 수준에서 수준 모르는 권한은 읽기로 셈. 테넌트에 걸린 수준 모르는 역할은 그 테넌트 소속 계정을 읽는다고 보지 않음 |
| 폼 응답자 모름 | 누구나 게시 간선으로 이미 옮긴 것이라 모름이 아님 |
| 관리자 신뢰 | 테넌트 권한이 설정 객체까지 관리로 내려가는 확정 관리자는 그 테넌트 SaaS 안 대상에 대한 파생 접근을 위협으로 보지 않음(관리자는 원래 못 보는 데이터를 보거나 못 가는 길을 쓰지 않는다는 전제). 다른 SaaS 대상은 그대로. 추적성 상실은 그대로. 채널, 저장소 같은 그릇 관리자는 일반 사용자 |
| 관리자 우회 | 관리자가 스스로 권한을 줘야 열리는 내용은 직접 권한 아님 |

### 파생 접근 (2026-11-16)

규칙은 엔진 `src/detection/threat/derived.ts` 한 곳. 판정(`judge.ts`)이 두 표로 유형을 붙이고, 추적성 상실이 호출자와 실행 신원 권한을 다시 씀(aegi-adapter-engine#443).

| 규칙 | 내용 |
|---|---|
| 정의 | 사람이 자동화, 실행 신원, 자격증명, 데이터 흐름, 효과, 접속자 권한 차용을 거쳐 닿는 곳과 수준 |
| 출발 | 누구나 공유를 뺀 자기 직접 권한과 소속. 누구나 공유에서 시작하는 파생은 누구나 노드가 한 번 냄 |
| 반복 | 사람마다 수준이 더 안 오를 때까지. 상한 없음. 접속자 권한 차용도 반복 안에서 같이 오름 |
| 두 표 | 전체 표는 모름 경로까지 따른 수준. 확정 표는 모름 사유가 없는 경로만 따른 수준. 판정 유형이 확정 표로도 서면 확정 |
| 모름 전파 | 단계에 들어가는 조건이 확정 표에서 서지 않으면 그 조건을 준 경로의 모름 사유를 단계 결과에 붙임 |
| 미확정 사유 | 호출자 모름, 결과 반환 모름, 능력 범위 모름, 실행 신원 수준 모름, 실행 신원 연결 추정 |
| 확정으로 두는 표시 | 실행 기록 없음, 게시 전용 |
| 고르는 순서 | 같은 대상, 같은 수준을 주는 경로가 여럿이면 확정 경로, 모름 사유가 덜한 경로, 게시 전용이 아닌 경로, 연동 지점 키가 작은 경로, 이유와 단계 키가 작은 경로 순으로 하나. 계산 차례와 상관없음 |

## 6. 추적성 상실

고정 실행 신원마다 네 조건. 넷 다 해당하면 추적성 상실.

| # | 조건 | 근거 |
|---|---|---|
| 1 | 실행 신원이 고정 | NIST SP 800-53 AC-2(9) |
| 2 | 신원 주인이 아닌 호출자 1명 이상(2026-11-17 결정, 전에는 호출자 2명 이상). 실행 신원이 사람 계정이면 그 사람이 주인, 봇, 앱, 위임 키처럼 사람 계정이 아닌 신원은 주인 없음. 여러 사람을 대표하는 공유 계정은 주인이어도 해당. 자격증명이 든 자원을 읽을 수 있는 사람도 호출자. 신원마다 따로 보고 조건을 채운 신원의 권한만 3번 수준에 넣음. 자동화, 토큰, 계정 사슬은 기록에 이름이 남는 끝 신원(계정)만 셈. 약하게 이어진 계정을 합치면 사라지면 미확정. 그 신원까지 실행 신원 사슬이 약하면(실행 신원 연결 추정) 미확정 | NIST SP 800-53 AC-2(9) |
| 3 | 실행 신원의 행위 수준. 읽기도 포함 | 읽기 기록도 요구할 수 있어 읽기 포함 |
| 4 | 대상 감사 로그에 호출자 없음 | NIST SP 800-53 AU-3 |

- 호출자 전원이 직접 읽기를 가진 대상과 공개 대상은 읽기 단계에서 제외.
- 대상 감사 로그로 확인하면 확정. 플랫폼 기본 동작으로만 보면 미확정.
- 직접 권한과 비교하지 않음. 같은 경로가 비인가 접근이나 권한 상승에도 걸리면 유형 둘이 붙음.
- 규칙 범위와 동작으로 자르지 않음(5절 규칙 9). 고정 신원이 여럿의 호출을 대신하면 그 신원이 한 일 전부가 기록에서 한 이름이 됨(2026-11-15 결정).

| 필드 | 뜻 |
|---|---|

| `primaryType`, `types[]`, `unconfirmedTypes[]` | 대표 유형(확정 위협이면 확정된 유형 중), 붙은 유형 전부, 확정 위협 안에서 미확정 경로에서만 나온 유형. 사람마다도 같은 칸 |

| `path.hops[]` | 간선마다 종류(직접 3종, 파생 6종 이름), 출발, 도착, 근거 `refs[]`(엔진 간선의 관계, 연결, 관측, 증거 키). 상위 범위에 준 권한이면 가장 가까운 범위 간선의 근거(수준이 있고 appliesTo 가 대상 종류를 덮는 간선만), 묶인 대상이면 대상마다 합침, 실행 신원 사슬이면 출발에서 그 신원까지 가는 모든 사슬의 간선 근거를 합침(사슬은 출발로 되돌아오지 않고 그 신원을 지나쳐 가지 않음. 사슬 중간의 고리는 고리 간선도 합침). 권한 간선은 판정에 필요한 수준(새 쓰기나 새 관리를 얻은 판정 줄이 있으면 쓰기 이상, 아니면 읽기)을 주는 간선을 출발, 소속 그룹(가장 가까운 그룹까지의 소속 간선과 그룹 권한 간선) 순으로 먼저 찾고, 없으면 수준과 상관없이 찾음. 직접 공유 간선의 출발은 같은 사람 계정 중 대상을 실제로 읽는 계정. 벤더 표 간선은 표가 읽은 속성(model, provider.objectType.property). 사람마다 연동 지점(데이터 흐름은 사본 쪽)에 닿는 간선의 종류는 `subjects[].entry`. 파생 계산이 남긴 단계를 사람 계정에서 이어 붙인 경로(판정 행의 `lead`)의 마지막 간선 |
| `severity`, `severityFactors` | 등급(아래 「심각도」)과 등급을 정한 사람(추적성 상실은 길)의 요소 점수. `people` 사람 수(공유 계정은 대표하는 사람 수, 등급에 안 쓰고 같은 등급 안 정렬에만 씀, 추적성 상실은 0). `likelihood` 가능성 요소 `size` 규모, `opportunity` 기회, `exploit` 공격 쉬움, `detection` 침입 탐지와 평균 `score`. `impact` 해당하는 영향 요소 `confidentiality` 기밀성, `integrity` 무결성, `availability` 가용성, `accountability` 책임 추적성(추적성 상실에만)과 평균 `score`. 점수는 0~9, 평균은 소수 둘째 자리. 화면은 등급만 보임(2026-11-18) |
| `headcount` | 화면에 보이는 인원(2026-11-20 결정). 누구나를 뺀 서로 다른 사람 수 `people`(공유 계정도 한 명)와 누구나가 사람에 있는지 `everyone`. 화면은 누구나를 숫자에 넣지 않고 「8명과 누구나」처럼 따로 붙임. 요약 문장, 차단 지점, 경로 그림이 이 값을 씀. 추적성 상실에는 없음 |
| `accessGap` | Access Gap 벤(아래 「Access Gap」). 비인가 접근, 권한 상승, 데이터 반출(조직 밖 직접 공유 포함) 위협에만 |
| `cuts[]` | 차단 지점(게시 때만 계산, 아래 「차단 지점」). 간선 `at`, 조치 종류 `action`(간선 종류로 정함), 함께 끊을 간선 `with[]`, 지운 그래프를 다시 판정해 닫힌 사람 수 `closes`와 위협의 사람 수 `of`(누구나도 한 명), 닫힌 사람을 `headcount` 와 같은 셈으로 센 `closed`(추적성 상실에는 없음), 모두 닫히면 `verified`, 다 안 닫히면 남은 사람이 같은 대상에 닿는 다른 연동 지점 `remainVia[]`, 같은 간선이 모두 닫는 다른 위협 수 `alsoCloses` |

### 심각도

2026-11-18 결정, 2026-11-19 값 재조정(engine #496). OWASP Risk Rating Methodology([원문](https://community.owasp.org/OWASP_Risk_Rating_Methodology))로 정함. 위험 = 가능성 x 영향. 요소마다 0~9 점을 매겨 평균하고 3 미만 LOW, 3 이상 6 미만 MEDIUM, 6 이상 HIGH 로 나눈 뒤 원문 표로 엮음. 등급은 CRITICAL, HIGH, MEDIUM, LOW 넷. 확실성은 등급에 쓰지 않고 화면의 「추정」 표시로만 씀. 사람 수는 등급에 쓰지 않고 같은 등급 안 정렬에 씀. CVSS 는 외부 공격자와 소프트웨어 취약점 관점이라 쓰지 않음(내부자 위협과 실수를 잡는 판정과 맞지 않음).

| 영향 | 가능성 LOW | 가능성 MEDIUM | 가능성 HIGH |
|---|---|---|---|
| HIGH | MEDIUM | HIGH | CRITICAL |
| MEDIUM | LOW | MEDIUM | HIGH |
| LOW | LOW(원문 Note) | LOW | MEDIUM |

가능성은 판정 행의 길 하나로 매김. 신호가 있는 네 요소만 평균하고 기술 수준, 동기, 발견 쉬움, 알려짐은 신호가 없어 뺌. 들어오는 자리는 사람이 자기 권한으로 처음 서는 자리(`lead` 의 시작, `derived.ts` `Chain.open`).

| 규모 | 들어오는 자리에 설 수 있는 사람. 관리자만 2(관리가 필요한 자리를 테넌트가 관리로 갖지 않음), 특정 채널이나 그룹 구성원 4(특정 사람, 특정 자원, 허용 호출자가 정해진 호출 포함. 그룹이나 계정이 부르는 자리는 조직 전원이나 누구나 노드가 그 주체를 읽을 수 있어도 그 구성원), 조직 전원 6(테넌트, 테넌트가 그 자리에 필요한 수준을 가진 자리. 부르는 자리는 테넌트가 부르는 데 필요한 수준까지 가질 때만), 누구나 9(누구나 노드이거나 누구나 노드가 그 수준을 가진 자리, 공개 폼, 공개 링크). 조직 밖 사람(조직 경계 모름 포함)은 특정 자리로 들어와도 5, 자리가 조직 전원이나 누구나면 6, 9 |

| 항목 | 기준 |
|---|---|
| 후보 | 그 위협의 사람(같은 사람 계정 포함)에서 접근이 퍼지는 방향으로 닿고 대상까지 이어지는 노드 사이의 간선 전부. 데이터 흐름과 범위는 거꾸로, 흐름을 옮기는 자동화는 받는 쪽에서, 접속자 권한 자동화는 그 호출자로 이어 봄. 같은 종류, 같은 두 객체 사이 간선은 한 후보 |
| 회수 가능 | 설정으로 회수할 수 있는 간선과 자동화 연결(호출, 데이터 흐름, 효과)만 후보. 자동화 연결은 트리거, 전달, 동작 설정이라 basis 와 상관없이 넣음(11-12 결정). 그 밖은 벤더가 적어 준 부여(관계 basis stated, decomposable 이 false 아님, Path_Rule_Schema_v1 「회수 지점」과 같음). 실행 신원 사슬은 모든 사슬이 회수 가능 간선을 지날 때, 자원 안 자격증명은 담은 관계가 회수 가능할 때 그 범위 간선(조치는 자격증명 제거). 벤더 표 간선은 표가 읽은 값이 설정일 때만(조직 밖 전달, 실행 방식). 본인 메일함, 받는 쪽 메일함, 작성자, 그 밖의 범위는 회수 불가 |
| 닫힘 | 후보를 지운 그래프의 연결 요소를 다시 판정해, 같은 사람이 같은 대상에서 이 위협이 연 접근을 다시 얻으면(연동 지점이 달라도) 열림. 접근은 데이터 반출이면 데이터 반출, 그 밖은 차원(읽기, 쓰기 이상)으로 봄. 기준선이 바뀌어 유형만 바뀌어도(권한 상승이 비인가 접근으로) 열림. 닫힌 사람 수를 셈 |
| 찾는 방법 | 후보를 묶음으로 지워 닫힌 사람이 있으면 반으로 나눠 다시 봄. 간선을 지우면 접근은 줄기만 해서, 묶음을 지워도 열린 사람은 그 안 간선 하나를 지워도 열림. 끝에 남는 간선 하나는 그 간선만 지운 판정이라 정확 |
| 조합 | 하나로 다 안 닫히면 가장 많이 닫는 간선을 지운 그래프에서 남은 사람을 닫는 간선을 다시 찾아 최대 3개. 하나로 닫히는 사람이 없으면 경로 그림과 진입 간선을 먼저 끊어 봄. 함께 지운 판정으로 모두 닫힐 때만 냄 |
| 순서 | 모두 닫는 조합, 닫는 사람 수, 경로 그림에 있는 간선, 키 순 |
| 추적성 상실 | 고정 실행 신원 간선이 모두 회수 가능하면 호출자 권한으로 바꾼 판정에서, 자원 안 자격증명이면 그 범위 간선을 지운 판정에서 그 신원의 추적성 상실이 사라지는지 확인 |
| 호출자 힌트 | 다시 판정할 때 그 위협의 사람만 계산하고, 접속자 권한 자동화의 호출자는 처음 전체 판정 결과를 씀. 지운 그래프에서는 실제보다 많을 수 있어 틀려도 위협이 남는 쪽으로만 틀림 |

경로 없음은 수집이 전수일 때만 「없음」. 아니면 「모름」. 받는 쪽 경계가 모름이면 미확정. 링크 공개와 외부 URL은 수신자를 모름.

### Access Gap

2026-11-17 결정, 2026-11-18 Access Gap 먼저(aegi-adapter-engine#489). 판정은 사람, 대상마다 Access Gap 줄(`judge.ts` `gapsOf`)을 먼저 세고 유형 규칙(`typesOf`)은 그 줄만 읽음. 판정 행은 그 줄의 기준선, 직접 수준, 가진 접근, 조직 밖 직접 공유를 싣고, 위협 하나(연동 지점과 대상)의 벤은 그 값을 모음. 그래서 위협의 사람과 Access Gap 사람이 같음. 코드 `threatGap.ts` `gapOf`, 게시 칸 `accessGap`.

| 항목 | 기준 |
|---|---|
| 비교 단위 | 사람, 대상, 읽기, 쓰기, 관리 |
| 기준선 | 조직 안은 판정이 본 직접 수준 D(확정 직접 권한과 누구나 공유 읽기). 조직 밖은 없음, 승인 목록에 있으면 읽기. 조직 경계 모름은 조직 밖으로 보고 미확정. 본인 객체와 조직 밖 객체는 대상이 아님 |
| 가진 접근 | 조직 안은 파생 접근. 조직 밖은 직접 공유(누구나 공유를 뺀 확정 직접 권한. 읽기 없는 게시도 넣고 누구나 노드의 게시는 뺌)와 파생 접근 중 높은 것. 직접 공유가 그 차원의 가장 높은 수준을 주면 연동 지점은 대상 자신 |
| 넣는 위협 | 비인가 접근, 권한 상승, 데이터 반출(조직 밖 직접 공유 포함, 2026-11-18 결정). 추적성 상실, 누구나 노드의 판정은 뺌 |
| 직접 권한 원 | 묶인 대상 가운데 하나라도 기준선 안 확정 직접 권한(누구나 공유 뺌)이 있는 사람. 승인 목록 밖 조직 밖 사람의 직접 공유는 원 밖, 승인된 사람은 읽기까지. 직접 권한만 있는 사람은 수준 높은 순 50명까지 싣고 수 `directCount`는 이 원의 인원 전부 |
| 파생 접근 원 사람의 직접 수준 | 판정이 본 수준. 조직 안은 누구나 공유 포함. 조직 밖은 직접 공유 가운데 기준선 안 수준. 직접 수준이 누구나 공유에서만 오면 `publicOnly` 를 달고 직접 권한 원 밖에 둠 |
| 파생 접근 원 | 이 연동 지점의 판정 행이 있는 사람 전부와, 이 연동 지점으로 닿지만 이 지점에서 새로 생긴 권한이 없는 사람(수에 넣지 않음). 수준은 그 판정을 준 가진 접근의 그 행 차원(읽기 행은 읽기, 쓰기 행은 쓰기 이상). 확정 판정은 확정 표 수준. 차원마다 가장 높은 수준을 준 경로의 연동 지점만 봄. 조직 밖 사람의 직접 공유는 `share` 에 그 수준을 달고 이 원에 둠(화면은 벤 칸 그대로, 사람 표 직접 권한 칸에 「직접 공유 읽기, 조직 밖」, 2026-11-18 결정) |
| 새로 생긴 권한 `gained[]` | 가진 접근이 기준선보다 높은 비트 |
| 권한 없는 접근자 `unauthorized` | 새로 생긴 권한이 있고 기준선 안 직접 권한이 없는 사람. 승인 목록 밖 조직 밖 직접 공유 사람 포함 |
| 권한 초과 접근자 `excess` | 새로 생긴 권한이 있고 기준선 안 직접 권한이 있는 사람 |
| 제외 `excluded` | 관리자 신뢰, 승인으로 위협에서 빠진 사람. 승인은 승인 범위(읽기) 안의 읽기, 직접 공유 읽기 포함(2026-11-18). 같은 위협이 있을 때만 파생 접근 원에 두고 두 수에서 뺌. 위협 행이 하나라도 있는 사람은 제외가 아님 |
| 확실성 | 사람마다 확정 또는 미확정. 판정의 확실성 그대로. 확정 사람이어도 미확정 판정 줄에서만 얻은 수준은 `unconfirmedGained[]`(2026-11-19 결정) |
| 접근 계정 `directAccounts[]`, `derivedAccounts[]` | 사람이 실제로 대상에 닿는 계정(같은 사람 계정 가운데, 키 순, 2026-11-20 결정). 대표 계정이 아님. 직접 권한 원 사람은 대상에 확정 직접 권한을 받은 계정(`JudgeResult.holderAccounts`, 직접 권한 계산의 권한별 계정). 파생 접근 원 사람은 판정 경로 첫 간선의 계정(위협 행 `lead`, 제외 행 `via`, 닿기만 하는 사람 `JudgedReach.accounts`), 조직 밖 직접 공유는 공유받은 계정. 같은 사람 계정이 아니면 싣지 않음. 대시보드가 벤 사람 칸에 그 계정의 SaaS 로고를 닮 |
| 게시 집계 `threat_access_gap` | 화면 첫 칸 숫자(2026-11-17 정의). 새로 생긴 권한이 있고 제외되지 않은 사람을 위협을 건너 중복 없이 셈 `people`. 한 위협에서라도 확정이면 `peopleConfirmed`, 미확정에서만 나온 사람은 `peopleUnconfirmed`. 그런 사람이 한 명 이상인 위협 수 `threats`. 코드 `threatGap.ts` `gapSummary` |

옛 다리 단위 Access Gap(`v2/accessGap.ts`, `v2/publishedGaps.ts`, 엔진 `policies.ts`와 원인 질의 `cause`, `know`, 집계 `access_gaps`)은 지움(2026-11-17 결정, aegi-adapter-engine#452). `snap_access_gaps` 표는 마이그레이션 0009 로 지움(다음 게시 때 적용). 성능 점수판(`gt:board`) 지표도 위협마다 벤 위에서 잼.

### 접근 표

2026-11-18 결정(aegi-adapter-engine#462). 대시보드 Explorer(경로 빌더)와 AI access 도구가 읽는 대상마다 사람별 접근. 대시보드는 접근을 직접 계산하지 않음. 원천은 판정의 Access Gap(`JudgeResult.access`, 위협 판정과 같은 기준선). 코드 `accessTable.ts`, 게시 계산 문서 `access_table`, 대시보드 `derived.access_table`.

| 칸 | 기준 |
|---|---|
| 대상 | 사람 하나라도 직접 권한이나 파생 접근이 닿는 모든 대상. 키 순 |
| `person` | 같은 사람 계정 묶음의 대표 계정 키(위협 `person` 과 같음). 누구나 공유는 `@everyone` 줄. 사람 키 순 |
| `direct` | 권한 간선이 닿는 수준 [읽기, 쓰기 2 또는 관리 3]. 확정과 모름 근거 전부, 수준 모르는 권한은 읽기 |
| `directSure` | 그중 확정 근거만. 누구나 공유 뺌. Access Gap 직접 권한 원과 같은 값 |
| `derived`, `derivedSure` | 파생 접근 수준과 확정 경로 수준. `derivedAt` 과 같은 값 |
| `points` | 그 수준을 준 연동 지점. 읽기 `r`, 쓰기 이상 `w`, 확정 경로 `rs`, `ws` |
| `gained` | 새로 생긴 권한. 수준(읽기, 쓰기, 관리)마다 `확정` 또는 `미확정`과 이유. 아래 규칙 |
| `accounts` | 표 맨 위 칸. 계정이 둘 이상인 사람의 계정(대표 포함, 키 순). 판정의 같은 사람 묶음(`JudgeResult.accountsOf`). 대시보드는 경로에 있는 그 사람 계정의 이름을 보이고 진입 계정이 어느 사람인지 이것으로만 찾는다(2026-11-18 결정, 브라우저는 같은 사람을 다시 가리지 않음). 계정 하나뿐인 사람은 싣지 않음 |
| 빈 칸 | 0 이거나 없으면 뺌 |

`gained` 는 위협 판정과 같은 Access Gap 이다. 대시보드는 이 칸을 읽기만 한다.

| 항목 | 기준 |
|---|---|
| 기준선 | 조직 안은 판정이 본 수준 D(확정 직접 권한에 누구나 공유 읽기를 합침). 조직 밖 사람의 Access Gap 대상은 없음, 승인 목록에 있으면 읽기. 그 밖의 대상(본인 객체, 조직 밖 객체)은 D |
| 새 권한 | 가진 접근이 기준선보다 높은 수준(threatGap `gainedOf`). 조직 안은 `derived`, 조직 밖은 직접 공유와 `derived`. 직접 공유로 선 수준은 `share: true`(2026-11-18 결정) |
| 미확정 이유 | 조직 안: 확정 경로로는 안 서는 수준(경로 모름 사유), 직접 수준 모름(약하게 이어진 사람 것 포함), 같은 사람 연결 약함, 같은 사람 연결 없음. 조직 밖: 경로 모름 사유, 조직 경계 모름 |
| 같은 사람 연결 | 조직 안 사람만. 약하게 이어진 사람이나 연결 없는 계정이 같은 사람일 수 있는 사람의 D 를 합치면 사라지는 수준 |
| 위협과 대조 | 비인가 접근, 권한 상승, 데이터 반출 위협 행(조직 밖 직접 공유 포함)의 새 권한은 모두 `gained` 에 있고, 확정 위협이면 확정 수준이 하나 이상 있음(시험 `accessTable.test.ts`) |

수준마다 가르므로 위협 행과 확실성이 다를 수 있다. 예: 약하게 이어진 사람이 쓰기를 가졌고 이 사람이 관리를 얻으면 위협 행은 관리로 확정, 표는 쓰기 미확정과 관리 확정.

r3 11-15(사람 65, 객체 3,575)에서 대상 2,264, 줄 9,087, 1MB, 압축 51KB, 계산 21ms. 새 권한 있는 줄 498, 위협 행 60건과 어긋남 0.

2026-11-18 운영 current(객체 3,609)에 게시한 문서는 2.66MB, 1MB 넘어 조각 11개로 나눠 실음.

## 11. 시험

- 시뮬레이션 사례 45개를 단위 시험으로. 기대 유형은 사람마다. 41/45 이상이 단계 4 끝난 기준.
- 정답 라벨은 사람마다 기대 유형(threat_types.yaml 이름). policy 는 채점에 쓰지 않음.
- 간선 속성 시험은 기존 결과 변화 없음을 같이 확인.
- 차단 지점은 `scripts/threat/cuts.test.ts`. 무작위 그래프 60개에서 간선을 하나씩 지워 전체를 다시 판정한 결과와 차단 지점 목록, 닫힌 사람 수가 같은지, 조합 값, 호출자 힌트 판정이 전체 판정과 같은지 대조. 11-12 실측에서 추적성 상실을 뺀 위협 30건도 간선 하나씩 지우는 전수 대입(위협마다 약 550개, 80초)과 대조해 놓친 차단 지점 없음.
