# 기존 시나리오 모음

끝점 SaaS 폴더로 나누기 전에 만들어 둔 Cross-SaaS 시나리오를 [시나리오 양식](../README.md#scenarioscsv)에 맞춰 한 파일에 모은 곳이다. 여기 있는 줄을 다듬어 끝점 SaaS 폴더의 `scenarios.csv`로 옮기면 이 파일에서는 지운다.

- 상태: 2026-11-25 옮김. `scenarios.csv` 267줄로 시작했다. 같은 날 끝점이 Atlassian·1Password 인 45줄을 [atlassian/scenarios.csv](../atlassian/scenarios.csv)·[onepassword/scenarios.csv](../onepassword/scenarios.csv)로 옮겨 지우고, 다른 끝점으로 넘길 5줄(BL-268~272)을 더해 227줄이다.
- BL-268~272 는 Atlassian·1Password 담당이 만들었지만 사람이 마지막으로 내용을 보는 곳이 Slack·Salesforce·GitHub 라 넘긴 줄이다. 경로의 Atlassian·1Password 위협 ID 는 `notes` 에 있다.
- BL-041, BL-042, BL-055, BL-076, BL-100, BL-137, BL-139, BL-150, BL-152, BL-157, BL-160, BL-166, BL-167, BL-169, BL-186, BL-194 는 Atlassian·1Password 부분만 옮겼다. 같은 줄에 다른 끝점 부분이 남아 지우지 않았다.
- 계정 이름과 테넌트 값은 역할 이름(개발자 A, 영업 담당 A 등)과 `(id)` 같은 자리 표시로 바꿨다. 시나리오가 정한 객체 이름(저장소, 프로시저, 규칙 이름)은 남겼다.

## ID

`BL-001`부터 차례로 붙인 번호다. 만든 때와 방식에 따른 예전 구분은 없앴고, 예전 번호는 `notes` 끝에 「옛 번호」로 남겼다. 끝점 SaaS 폴더로 옮길 때 그 폴더의 `SC-<SAAS>-<번호>`를 새로 받는다.

## 읽을 때

- 같은 시나리오가 여러 줄로 있다. 만든 때가 달라 따로 적힌 것을 합치지 않고 그대로 옮겼다. 예: 슬래시 명령으로 개발자 개인 토큰이 커밋에 쓰이는 경로는 `BL-011`, `BL-140`, `BL-174`, `BL-192` 네 줄이다.
- `saas_path`는 경로 문장에 나오는 단어 순서로 자동으로 뽑은 값이다. 순서가 틀리거나 SaaS가 더 붙은 줄이 있다. 옮길 때 고친다.
- `threat_type`은 모든 줄에 있다. 실행해서 분류한 줄을 뺀 나머지 상당수는 경로 패턴 단위로 한꺼번에 붙인 추정이고 `notes`에 「위협 유형은 경로 패턴 기준 추정」이라고 적었다. `end_threat_ids`는 비어 있다.
- `status`는 지금 시험 테넌트(4회차) 기준이다. 2~3회차는 테넌트가 달라, 그때 성립했거나 세팅돼 있던 것은 `status`를 `후보`로 두고 결과를 `evidence`에 회차와 함께 적었다. `성립`은 4회차에서 확인한 것뿐이다.
- 질문으로만 적어 둔 줄의 `evidence`는 2~3회차에 그 연결이 실제로 있었는지다. 「연결 실측 있음」은 당시 환경에서 연결을 확인했고 시나리오는 실행하지 않았다는 뜻이다.
- 같은 시나리오를 두 회차에서 본 줄은 `evidence`에 둘 다 적고 예전 줄의 ID를 괄호로 달았다.

## 넣지 않은 것

위협으로 볼 수 없는 29줄은 옮기지 않았다(2026-11-25).

- 시나리오로 세지 않기로 한 것 20줄: 모델 취약점에 기대는 프롬프트 주입 사례, 공격자의 토큰 탈취가 전제인 사례, 실행해 보니 권한을 넘지 않아 후보에서 뺀 것
- 자기 권한 안에서만 도는 것 5줄
- 실행해서 성립하지 않은 것 2줄
- 권한 격차가 없거나 실행이 실패한 체인 2줄
