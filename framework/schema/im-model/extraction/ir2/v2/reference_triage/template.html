v2 판단표 4차: 관계 없는 객체와 객체 참조

v1 실측 데이터셋(객체 __OBJECTS__, 관계 __RELATIONS__)에서 관계에 한 번도 나오지 않는 객체를 세고, 그 객체가 가진 참조를 관계로 올릴지 정합니다. 결정은 v2 대장(relation_decisions_v2.json)에 기록하고 v1 고정 기록은 바꾸지 않습니다.

  • 관계 없는 객체는 __ORPH__개입니다. 관계의 출발, 도착 칸만 세면 __NO_ST__개지만, 그중 역할 객체 __BY_ROLE__개는 has_role_on의 역할 칸에 들어 있어 이미 연결돼 있습니다.
  • 새로 관계로 올릴 것은 5건입니다(A). Okta 그룹 규칙, Okta 리소스 세트, GitHub 조직과 엔터프라이즈, GitHub 조직 웹훅, Google과 Okta 사용자의 tenant 소속입니다.
  • 그래프에도 탐지 엔진에도 없는 것이 2종 __CA__ + __TOK__개입니다(B). GitHub 자격 증명 승인과 Google OAuth 토큰입니다. 관계가 아니라 엔진 규칙으로 다루기를 권합니다.
  • 배정 객체를 2홉으로 바꾸지 않습니다(C). 배정 __ASSIGN__개는 has_role_on이 속성으로 가리키고 있어 사실이 이미 그래프에 있습니다.
  • 배정되지 않은 역할, 빈 그룹 등 D의 객체는 연결이 없는 것이 맞습니다. 그대로 둡니다.

정할 것

  1. A의 Q01, Q03, Q04, Q05를 관계로 만들지
  2. Q02 리소스 세트: 대상은 org 그대로 두고 범위 참조를 더할지(aegi-schema 제안 필요), 대상을 리소스 세트로 바꿀지
  3. B의 Q06, Q07을 관계 없이 엔진 과제로 기록할지
  4. C의 배정 객체 2홉 개편을 하지 않는 것으로 기록할지
