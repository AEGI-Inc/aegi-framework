# 컴플라이언스 범위 확정 (2026-11-11)

원본 판정 기록 `../items-clean/scope-final.jsonl`(모든 항목의 단계와 사유)에서 산출한 범위 확정 요약이다.

판단 기준: 데이터로 판정할 수 있는 기술 조치만 남기고, 애매하면 뺀다. 점검이 통제의 본뜻을 판정하는가, 우리가 볼 수 있는 조각에 맞춰 좁게 해석했는가를 본다.

- SaaS 적용 판정: 정책, 절차, 인사, 물리 보안, 계약, 법 절차처럼 SaaS 객체로 가리킬 대상이 없는 항목. 항목별 사유는 `scope-final.jsonl`.
- PIPA 는 35개 문서 가운데 SaaS 를 쓰는 처리자에 해당하는 8개 문서만 조항으로 나눴다. 나머지 27개 문서(마이데이터 전송, 소송, 고발 기준 등)는 문서 단위로 뺐다.

## ISO 27001

### 범위 안

- 5.14 정보 전송 (자동 판정): DLP, 외부 수신 경고, Chat 외부 공유 설정이 정보 전송 규칙을 직접 판정한다
- 5.15 접근 통제 (자동 판정): 세션, IP, 인증 정책과 우회 위협이 접근통제 규칙을 판정한다
- 5.16 ID 관리 (자동 판정): 장기 미로그인 계정, IdP 에서 정지된 사용자의 남은 계정(AEGI 자체 점검)과 프로비저닝 점검이 계정 수명주기를 판정한다
- 5.17 인증 정보 (자동 판정): 비밀번호 정책 점검이 인증 정보 관리를 직접 판정한다
- 5.18 접근 권한 (자동 판정): 권한 배정과 우회, 상승, 위임, 속성 위협이 접근 권한 관리를 판정한다
- 5.23 클라우드 서비스 이용 시 정보보호 (근거 제공): 서드파티 앱과 연동 관리. 앱 권한 범위 점검을 추가해 판정한다
- 8.1 사용자 단말 (자동 판정): 기기 암호화, 화면 잠금 비밀번호, 관리 승인(AEGI 자체 점검)과 기기 정책 점검이 단말 보호를 판정한다
- 8.12 데이터 유출 방지 (자동 판정): DLP, 시크릿 스캐닝, Takeout, 다운로드 제한 점검
- 8.16 모니터링 (자동 판정): GWS 경보 규칙 점검
- 8.2 특수 접근 권한 (자동 판정): 관리자 수, 관리자 MFA, 다중 승인 점검이 특수 권한 관리를 판정한다
- 8.24 암호 사용 (자동 판정): 인증서 만료, 키 크기 점검(키 관리)
- 8.3 정보 접근 제한 (자동 판정): 공유 드라이브 접근, 외부 공개 개체 점검과 노출 위협
- 8.4 소스 코드 접근 (자동 판정): 저장소 권한, 공개 범위, 포크 점검. 소스 코드 통제라 GitHub 가 본 대상이다
- 8.5 안전한 인증 (자동 판정): MFA, 피싱 방지 인증 점검
- 8.7 악성코드 대응 (자동 판정): SaaS 테넌트의 악성코드 방어 설정(메일 첨부, 링크 보호). 단말 백신은 범위 밖

### 본뜻 판정으로 제외 26

- 5.11 자산 반납: 물리 자산 반납이 본뜻이다. SaaS 쪽 권한 회수는 5.18, ISMS-P 2.2.5 에서 본다
- 5.12 정보 분류: 분류 체계를 정하고 운영하는 것이 본뜻이라 조직 문서로 확인한다. SaaS 에서 읽을 수 있는 것은 라벨 정의 일부(Salesforce 필드 분류, Drive 라벨은 지금 수집 권한으로는 읽지 못함)뿐이라 통제를 판정하지 못한다
- 5.13 정보 표시: 분류에 맞게 라벨을 붙이는 절차가 본뜻이라 조직 문서로 확인한다. 파일, 필드에 붙은 라벨 일부만 읽을 수 있어 통제를 판정하지 못한다
- 5.3 직무 분리: 상충 직무 정의는 회사가 한다
- 5.33 기록 보호: API 로 판정할 수 있는 것이 Okta 로그 스트리밍 하나뿐이다
- 5.34 개인정보 보호: 8.12 와 같은 DLP 점검을 다시 쓴 것이다. 개인정보는 PIPA 안전성 확보조치 기준에서 다룬다
- 5.9 정보와 관련 자산 목록: 자산 목록 작성은 절차이고 위반을 말할 기준이 없다
- 6.7 원격 근무: 5.15, 8.22 와 같은 IP 점검을 다시 쓴 것이고 원격 근무의 본뜻과 거리가 있다
- 7.14 장비 안전 폐기·재사용: 기기 폐기 전 삭제 검증은 물리 절차다
- 7.9 외부 반출 자산 보호: 사외 반출 기기의 분실, 도난 대비는 물리 관리다
- 8.10 정보 삭제: 자동 판정 점검 없이 사람 확인 항목만 있어 SaaS 자동 점검 범위에서 제외
- 8.11 데이터 마스킹: 연결 점검이 화면 표시 옵션이라 데이터 마스킹이 아니다
- 8.13 정보 백업: 백업 생성과 복구 시험은 SaaS API 로 보이지 않는다. 백업 앱 연동은 간접 신호뿐이다
- 8.15 로그 기록: 자동 판정 점검 없이 사람 확인 항목과 미수집 점검만 있어 SaaS 자동 점검 범위에서 제외
- 8.19 운영 시스템 소프트웨어 설치: SaaS 앱 설치는 5.23 과 겹치고 근거가 1개다
- 8.22 네트워크 분리: 본뜻은 망 구간 분리다. IP 허용 목록은 5.15 접근통제에 속한다
- 8.25 안전한 개발 생명주기: 본뜻은 개발 전 과정(요구사항, 설계, 보안 코딩, 시험, 교육)의 보안 규칙이다. 연결 점검은 GitHub 병합 관문(브랜치 보호)뿐이라 좁은 해석이다. 저장소 접근은 8.4 에서 본다
- 8.28 시큐어 코딩: 시크릿 스캐닝은 8.12 에 속한다. 코드 스캐닝(CodeQL)은 수집하지 않는다
- 8.29 개발·인수 보안 시험: 병합 전 상태 검사 1개로는 보안 시험을 판정할 수 없다
- 8.30 외주 개발: 외주 인력 목록과 감독은 회사 절차다
- 8.31 개발·시험·운영 환경 분리: 환경 구분 테넌트 목록이 필요하고 SaaS 마다 테넌트 하나만 본다
- 8.32 변경 관리: 본뜻은 모든 변경의 공식 절차다. GitHub PR 승인은 8.25, 8.4 에 남는다
- 8.33 시험 정보: 시험 데이터 선정과 보호는 개발 절차다
- 8.34 감사 시험 중 정보시스템 보호: 감사 시험 계획 합의는 절차다
- 8.8 기술 취약점 관리: SaaS 취약점은 제공자 몫이고 코드 의존성 경보 일부만 보인다
- 8.9 구성 관리: 구성 정의와 관리 절차가 본뜻이고 판정 점검이 없다

## ISMS-P

### 범위 안

- 2.10.2-02 클라우드 보안 (자동 판정): SaaS 보안 구성 기준 점검 전체가 클라우드 보안 설정 항목 그 자체다
- 2.10.2-03 클라우드 보안 (자동 판정): SaaS 관리자 수, 관리자 MFA, 관리 콘솔 세션 점검이 클라우드 관리자 권한 통제를 판정한다
- 2.10.5-02 정보전송 보안 (자동 판정): 메일 TLS, MTA-STS, 웹훅 HTTPS 점검이 외부 전송 구간 암호화를 판정한다

- 2.2.5-02 퇴직 및 직무변경 관리 (자동 판정): IdP 에서 정지된 사용자의 남은 계정(AEGI 자체 점검)과 퇴사자 계정 점검이 권한 회수를 판정한다
- 2.3.1-01 외부자 현황 관리 (근거 제공): SaaS 의 외부 계정, 게스트, 외부 연결 조직을 보여 주고 승인 없는 초대를 점검한다. 위탁 계약 현황은 범위 밖
- 2.5.1-01 사용자 계정 관리 (자동 판정): 계정 발급, 기본 계정, 미사용 계정, 퇴사자 계정 점검이 계정 관리를 판정한다
- 2.5.1-02 사용자 계정 관리 (자동 판정): 역할, 저장소, 공유 기본 권한 점검과 우회, 위임, 속성 위협이 최소 권한 부여를 판정한다
- 2.5.2-02 사용자 식별 (자동 판정): 공용 자격증명 위협과 비전용 계정 토큰 점검이 공용 계정 사용을 판정한다
- 2.5.3-01 사용자 인증 (자동 판정): SSO, MFA, 로그인 실패 잠금 점검이 사용자 인증을 판정한다
- 2.5.3-02 사용자 인증 (자동 판정): 외부 접속 MFA, 기기 기반 접근 정책 점검이 강화 인증을 판정한다
- 2.5.4-01 비밀번호 관리 (자동 판정): 비밀번호 길이, 복잡도, 재사용, 만료 정책 점검
- 2.5.4-03 비밀번호 관리 (자동 판정): 계정 복구, 백업 코드, MFA 등록 시 본인 확인 점검이 인증수단 관리를 판정한다
- 2.5.5-01 특수 계정 및 권한 관리 (자동 판정): 슈퍼 관리자, 조직 소유자 수 점검과 상승, 위임 위협이 특수 권한 최소화를 판정한다
- 2.5.5-02 특수 계정 및 권한 관리 (근거 제공): 슈퍼 관리자 일상 사용, 비전용 계정 토큰 점검이 특수 계정 분리를 판정한다
- 2.6.2-02 정보시스템 접근 (자동 판정): 유휴 세션 시간 제한 점검
- 2.6.3-01 응용프로그램 접근 (자동 판정): 보안 그룹 접근 통제 점검과 노출, 우회, 속성 위협이 앱 권한 차등을 판정한다
- 2.6.3-02 응용프로그램 접근 (자동 판정): 앱 세션 유휴 시간 점검. 동시 세션 제한은 점검이 없다
- 2.6.3-03 응용프로그램 접근 (자동 판정): 관리 콘솔 인증 정책(피싱 방지, MFA) 점검
- 2.7.1-02 암호정책 적용 (자동 판정): 전송 구간 TLS, 클라이언트 측 암호화 설정 점검. SaaS 저장 암호화는 제공자 몫이라 범위 밖
- 2.7.2-02 암호키 관리 (자동 판정): 저장소 밖 비밀, 노출 토큰, 배포 키, 인증서 점검과 공용 자격증명 위협이 키와 자격증명 관리를 판정한다
- 2.8.5-01 소스 프로그램 관리 (자동 판정): 저장소 공개 범위, 관리자 수, 포크, 푸시 대상 제한 점검이 소스 코드 접근통제를 판정한다
- 2.9.4-01 로그 및 접속기록 관리 (자동 판정): SaaS 감사 로그 보관, 외부 전송 점검
- 2.9.4-02 로그 및 접속기록 관리 (자동 판정): 로그를 SaaS 밖으로 전송해 보관하는지와 Vault 관리자 보호 점검이 로그 위변조 방지를 판정한다
- 2.9.4-03 로그 및 접속기록 관리 (근거 제공): 로그 보관 기간 점검. 법정 기록 항목을 모두 담았는지는 볼 수 없다

### 본뜻 판정으로 제외 21

- 2.1.3-01 정보자산 관리: 보안등급별 취급 절차다. 등급 정보를 수집하지 않는다
- 2.1.3-02 정보자산 관리: 자산 책임자 지정은 조직 절차다. 연결 점검이 CODEOWNERS 파일 하나라 본뜻과 거리가 멀다
- 2.10.1-04 보안시스템 운영: 본뜻은 보안 정책 예외 등록 절차다. 연결 점검(스팸 필터 우회, 브랜치 보호 우회)은 개별 설정이라 좁은 해석이다
- 2.10.1-05 보안시스템 운영: 보안 규칙의 주기적 타당성 검토는 절차다. 검토했는지는 API 로 보이지 않는다
- 2.10.2-04 클라우드 보안: 설정 정기 검토는 절차다. 연결 점검은 일반 보안 경보라 2.11.3 에서 본다
- 2.2.1-02 주요 직무자 지정 및 관리: 주요 직무자 지정은 인사 절차다. 관리자 수 점검은 2.5.5 에서 본다
- 2.2.1-03 주요 직무자 지정 및 관리: 개인정보취급자 지정은 인사 절차다. 접근 권한 최소화는 안전성 확보조치 기준 제5조에서 본다
- 2.2.2-01 직무 분리: 상충 직무 정의는 회사가 한다(ISO 5.3 과 같은 판단)
- 2.3.4-01 외부자 계약 변경 및 만료 시 보안: 계약 종료 외부자 명단이 필요하다. 계정 회수 점검은 2.2.5 에서 본다
- 2.5.2-01 사용자 식별: 식별자 고유성은 SaaS 가 보장하고, 연결 점검(초대 이메일 도메인)은 식별자 규칙의 본뜻이 아니다
- 2.5.4-02 비밀번호 관리: 고객(정보주체)용 서비스의 비밀번호 규칙이다. 우리가 보는 것은 직원용 SaaS 다
- 2.5.6-01 접근권한 검토: 자동 판정 점검 없이 사람 확인 항목과 미수집 점검만 있어 SaaS 자동 점검 범위에서 제외
- 2.5.6-02 접근권한 검토: 접근권한 정기 검토는 절차다. 남은 불필요 권한 점검은 2.5.1, 2.5.5 에서 본다

- 2.8.3-01 시험과 운영 환경 분리: 환경 분리 대상 테넌트 목록이 필요하고 SaaS 마다 테넌트 하나만 본다(ISO 8.31 과 같은 판단)
- 2.8.3-02 시험과 운영 환경 분리: 개발과 운영 혼용 환경의 보완대책은 절차다
- 2.8.4-01 시험 데이터 보안: 시험 데이터 선정은 개발 절차다(ISO 8.33 과 같은 판단)
- 2.8.4-02 시험 데이터 보안: 시험 데이터 승인과 삭제는 개발 절차다
- 2.8.5-02 소스 프로그램 관리: 본뜻은 소스 코드의 비상 대비 분리 보관이다. 연결 점검이 브랜치 보호 규칙이라 좁은 해석이다
- 2.8.5-03 소스 프로그램 관리: Git 사용 자체가 변경 이력을 남긴다. 연결 점검이 브랜치 보호 규칙이라 좁은 해석이고 저장소 접근은 2.8.5-01 에서 본다
